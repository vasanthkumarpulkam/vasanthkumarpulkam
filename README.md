### About

Senior Data Engineer with 7+ years building cloud data platforms on AWS, Azure, Databricks and Snowflake. I work across the full data life cycle: collection, ingestion, storage, processing and visualization.

- Building batch and streaming pipelines with **Spark, Kafka and Delta Lake**, orchestrated with **Airflow** and shipped through **Jenkins, GitHub Actions, GitLab CI/CD and Terraform**
- Migrating legacy **Informatica and SSIS** workloads onto **Databricks and AWS Glue**, and turning nightly batch into Structured Streaming
- Working in regulated domains: banking and payments, telecom, fintech, with **PCI-DSS aligned governance, PII and PHI tokenization, and end to end lineage**
- **AWS Certified Data Engineer**, **AWS Certified Solutions Architect**, **Databricks Certified Data Engineer Professional**, **Microsoft Certified Fabric Data Engineer**
- M.S. Computer and Information Science, University of North Texas
- Reach me at **vasanthkumarpulkam@gmail.com**

**Portfolio:** https://vasanthkumarpulkam.github.io/portfolio/

### What I actually work on

<table>
<tr><td width="33%" valign="top">

**Streaming that survives contact**

Kafka into Delta with schema enforcement and watermarking, replacing brittle nightly batch. The interesting part is not throughput, it is what happens when a producer changes shape at 2am.

</td><td width="33%" valign="top">

**Governance as code**

Reusable Spark modules for tokenization, masking and validation, shared across data domains rather than reimplemented per pipeline. Lineage you can hand to an auditor.

</td><td width="33%" valign="top">

**Explainable models**

Side work on risk scoring pairs a deterministic factor model with Explainable Boosting Machines. A model that cannot explain its output is not deployable, whatever its AUC.

</td></tr>
</table>

### About

I build systems that turn messy real-world data into decisions — risk models, retrieval pipelines, and marketplaces that have to be correct about money and permissions.

- 🎓 Graduate data-science work at the **University of North Texas** (DSCI 5260) — 880k+ Chicago collision records, speed zones, signal effectiveness, severity modelling
- 🔭 Currently extending my **RAG assistant** toward OpenSearch and AWS Bedrock, and adding proper CI across my projects
- 🧠 Interested in the point where a model stops being deployable — **explainability, calibration, and access control**
- 💬 Ask me about **FastAPI, Supabase row-level security, FAISS retrieval, or scikit-learn / XGBoost / EBM pipelines**
- 📫 Reach me at **vasusai8008@outlook.com**

### What I actually work on

<table>
<tr><td width="33%" valign="top">

**Explainable ML**

Insurance rating is a good forcing function: a model that can't explain its output isn't deployable, whatever its AUC. So the rating engine pairs a deterministic factor model with Explainable Boosting Machines.

</td><td width="33%" valign="top">

**RAG from primitives**

Built without LangChain on purpose — ingestion, chunking, embedding, indexing and prompt assembly are all written out, because that's where chunk size and retrieval depth actually change answer quality.

</td><td width="33%" valign="top">

**Real access control**

Multi-sided marketplaces are mostly a permissions problem. My Supabase builds enforce access in Postgres RLS rather than in application code — the database is the only layer that can't be bypassed.

</td></tr>
</table>
